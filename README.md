# custom-linter

`custom-linter` — это статический анализатор на Go для проверки текстов лог-сообщений.
Он находит проблемы в строковых литералах и предлагает автоматические исправления.

Поддерживаются вызовы логирования из:
- стандартного пакета `log`,
- `log/slog`,
- `go.uber.org/zap` (`Logger` и `SugaredLogger`).

## Что проверяет линтер

Правила настраиваются через конфиг и по умолчанию включены:
- `lowercase`: сообщение должно начинаться с маленькой буквы.
- `english`: сообщение должно содержать только английские буквы.
- `symbols`: в сообщении не должно быть запрещенных/подозрительных символов.
- `sensitive`: в сообщении не должно быть потенциально чувствительных слов.

Реализации правил находятся в `internal/rules/*`.

## Конфигурация

Линтер читает YAML-конфиг из переменной окружения `LINTER_CONFIG`.
Если переменная не задана, используются настройки по умолчанию (все правила включены).

Пример `rules.yaml`:

```yaml
lowercase: true
english: true
symbols: true
sensitive: true
```

Чтобы отключить правило, установите для него `false`.

## Установка

Установить бинарник в `$GOBIN` (или `$GOPATH/bin`):

```bash
go install ./cmd/customlinter
```

## Запуск

Настройте путь к конфигу:

```bash
export LINTER_CONFIG="path/to/rules.yaml"
```

Проверка всех пакетов текущего модуля:

```bash
customlinter ./...
```

Проверка конкретного пакета:

```bash
customlinter ./internal/analyzer
```

## Тесты

Анализатор тестируется через `analysistest` и golden-файлы в `internal/analyzer/testdata/src`.

Запуск всех тестов:

```bash
go test ./...
```

## Структура проекта

- `cmd/customlinter/main.go` — точка входа CLI (`singlechecker`).
- `internal/analyzer/analyzer.go` — логика анализатора и диагностики с предложениями исправлений.
- `internal/config/config.go` — схема YAML-конфига и загрузка.
- `internal/rules/` — движок правил и их реализации.
- `internal/analyzer/testdata/src/` — тестовые фикстуры и golden-вывод.
- `rules.yaml` — пример конфигурации.

## Примечания

- Диагностики создаются для поддерживаемых вызовов логирования.
- Автоисправление применяется к первому строковому аргументу вызова.
- Сейчас проверяются только строковые литералы; динамические выражения пропускаются.
